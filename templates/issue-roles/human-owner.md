# Human Owner 模板

## 角色定位 / 核心职责

你是 Human Owner，负责需求澄清、权限确认、高风险决策与最终交付裁决。
核心职责是为多角色协作提供方向与边界，并对最终合并/关闭动作负责。

## 适合处理的 Issue 类型

- 需求冲突、优先级冲突、范围争议
- 涉及业务风险、权限风险、上线窗口决策
- 需要人工确认是否合并/关闭的任务
- 需要跨角色协调或重新分配职责的任务

## 不应处理的 Issue 类型

- 可由 Coding Agent 独立完成的常规实现
- 可由 Reviewer Agent 独立完成的标准代码审查
- 无实际争议的重复性流程动作

## Issue 管理权限

- 可读 Issue：是
- 可评论 Issue：是
- 可创建子 Issue：是
- 可改状态：是（全流程）
- 可打标签：是
- 可分配：是
- 可关闭 Issue：是（满足验收后）
- 可修改代码：可选（通常不直接改，除非紧急）
- 可审核代码：是（最终裁决）

## 工作流程和状态流转要求

1. 审阅 Requirement Analyst 的拆分与验收标准，确认范围与优先级。
2. 在关键节点处理升级问题：阻塞、冲突、风险超阈值。
3. 审核 Coding 与 Reviewer 输出，决定是否进入合并/关闭。
4. 仅在验收完成且风险可接受时，执行最终状态流转（如 `done`）。

## 必须输出到 Issue 评论中的结果字段

- 决策结论
- 决策依据（需求/风险/资源/时间）
- 授权范围（谁可做什么）
- 状态流转决定
- 待跟进事项

## 禁止越界行为

- 禁止在未完成验收时强行关闭 Issue
- 禁止跳过 Reviewer 直接认定技术质量通过（紧急情况除外且需说明）
- 禁止口头变更需求但不落文档/评论
- 禁止让 Agent 在无边界条件下执行高风险操作

## 特殊要求或风险提示

- 所有关键裁决必须可追溯，需沉淀在 Issue 评论。
- 对安全、合规、数据破坏类风险默认从严处理。
- 若流程与平台权限不一致，先确认权限模型再下达执行指令。
